## 功能模块细节

- 项目：新增、编辑、删除、搜索、分页、项目切换；所有者、编辑者、观察者权限。
- 能力中心：模型、Skill、MCP、Agent 配置；Agent 可关联同一项目中的模型与工具；密钥 Fernet 加密保存、只写不回传。
- 测试资产：文档、用例、计划、流程的 CRUD、状态与名称筛选、分页、CSV 导出。用例步骤/预期结果，计划和流程顺序编排，支持关联执行 Agent。
- 执行：HTTP 请求只创建排队记录并立即返回 202，独立 Worker 执行模拟测试并生成报告，浏览器每 2 秒轮询。可取消执行。
- 报告：执行状态、进度、用例结果、步骤、日志、统计、事件历史及附件关联全部入库；提交时保存资产与所选 Agent/资源名称快照，修改或删除原资产不影响报告。支持 JSON 导出。
- 文件：本地随机文件名存储；单文件最大 10 MB；下载、删除经过项目权限校验；支持文档、报告附件及按用例/步骤关联截图。
- 工作台：数据库聚合统计、最近七天模拟测试趋势、资源概览与最近执行。
- AI 工作室：LangGraph 编排“检索上下文 → 生成 → 覆盖检查 → 优化 → JSON 校验”，支持真实 OpenAI 兼容模型与模拟规则引擎、Prompt/用例模板/策略、Token 用量与完整任务追踪。
- 需求拆解与模块用例：按 Markdown 标题保留全文层级和原文，真实模型逐节点提取前置条件、流程、校验、异常、特殊逻辑与待确认项，再按指定模块的六类维度生成单校验点用例；结果存入任务历史，可导出 Markdown 并按需写入用例资产。模拟模式只展示原文结构，不生成用例。
- 需求管理：独立 `/requirements` 工作台，支持层级目录、标题/负责人/标签搜索、状态与优先级筛选、验收标准、版本对照和恢复，以及需求到模块、用例、任务的来源追踪。工作台文档入口支持 Markdown、Word（不超过 10MB），解析完成后刷新正文；另保留 JSON 导入导出。
- 知识库：文档分块、本地哈希向量或真实嵌入模型、可选 Reranker、项目隔离检索与引用追踪。
- 用例增强：功能模块、等级、类型、前置条件、备注、步骤、列表/思维导图、拖拽归类、复制粘贴、CSV/JSON 导入导出、测试套件。
- 接口自动化：OpenAPI 同步、环境、Header、变量、声明式前后置函数、变量提取、HTTP 与数据库只读断言、批量任务与报告。
- UI 自动化：用步骤编辑器维护 Web 与 App 用例；Web 可从「录制」进入平台内 Chromium，采集页面字段操作并保存为待复核用例，也支持导入已有 Playwright Trace ZIP。App 可连接真实 Android 设备，通过设备画面操作并按资源 ID、无障碍描述或文本字段记录；也可上传不超过 100 MB、最长 10 分钟的视频，由视觉模型抽取最多 12 个关键帧并生成未验证用例。真实 Web 回放支持 1–20 轮稳定性检查、慢步骤/页面异常采集，并为每轮保存截图、WebM 视频和 Trace。
- 失败定位与修复：真实接口/UI 执行后可查看本地规则分诊；证据不足时可选择已验证的真实模型进行失败分析。模型判断为用例问题且返回完整、可校验的修复配置后，项目编辑者可应用修复并自动排入重试任务；版本冲突、配置校验失败或模型未提供修复配置时不会自动改写用例。模拟执行不调用真实模型，也不会伪装成真实诊断。
- Agent 与 MCP：项目对话、Agent/Skill 指令、远程 Streamable HTTP MCP、工具参数审批、连接测试。
- 治理：用户、组织、项目角色、30 天项目 API Key、深浅主题、中英文界面、操作审计及保留策略。

## 典型使用流程

1. 选择或创建项目。
2. 在需求管理上传或编辑需求。进入「测试用例」，点击「生成用例」，选择需求文档、单个模块或全部模块、模型和生成 Skill；也可从 `ui-testcase-generation` Skill 卡片直达生成弹窗。此入口不要求指定每模块数量：后台逐项分析需求节点，由模型按可测试规则与适用场景决定用例数量，并记录无法形成合格用例的覆盖缺口。选择 `ui-testcase-generation` 时按其 JSON 数组、优先级、前置条件、多步操作与预期格式生成。真实模型任务完成后自动写入对应模块的用例列表，可用模块筛选查看。模拟拆解只展示原文结构，不生成或写入用例。任务详情保留分级规则、原文、用例表与 Markdown 导出。
3. 在知识库建立文档并上传附件；后台完成解析、分块与向量化后可检索。
4. 在模型管理配置 OpenAI 兼容基址、模型名和密钥，执行连接测试后进入真实模式；未配置时使用明确标记的模拟生成。
5. 在 AI 工作室选择需求、知识库、模板和策略，生成或优化功能/API/UI 用例；任务结果经结构校验后写入资产。
6. 在接口自动化或 UI 自动化选择环境，以真实/模拟模式提交任务；真实执行由 Worker 完成。
7. App 录制需选择已启用的 Mobile MCP、在线 Android 设备和应用包名；点击设备截图中的控件记录元素字段。已有 App 录屏可在录制页上传，并选择支持图片输入的已验证模型进行异步分析。视频帧会发送到所选模型服务，上传前应遮挡密码、验证码及个人信息。生成的 App 用例标记为“未验证”，需要补充测试数据、预期结果并复核字段定位后执行。
8. 真实接口/UI 执行失败时，可先查看任务逐步日志、截图、视频与 Trace，再从任务详情发起本地规则分诊或真实模型分析。模型提出的修复方案需要经过平台配置校验；满足条件后，由有编辑权限的用户点击“应用修复并继续执行”。应用操作会增加用例版本并新建重试任务，原执行记录和历史版本保留。
9. 在任务中心查看输入快照、RAG 引用、阶段日志、Token 用量、响应、截图、视频与 Trace。
10. MCP 工具真实调用先进入待审批状态，只有项目所有者批准后才执行。

AI 工作室可多选项目 Skill；留空时后端按任务自动匹配：需求评审使用 `requirements-review`，接口文档评审使用 `api-doc-review`，功能/UI 用例生成使用 `ui-testcase-generation`，接口用例生成使用 `api-testcase-generation`，接口断言和 UI 执行分别使用 `api-test-assertion` 与 `web-app-test-execution`。任务会冻结 Skill 快照，并在“流程与日志”中记录实际使用的 Skill。

功能用例模拟结果由 `data.simulate_result` 决定，支持 `passed`、`failed`、`skipped`。接口/UI/AI 任务的模拟模式不会发送请求或启动浏览器；结果会标注 `simulation` 或 `skipped`，不会伪装为真实执行。`completed` 表示任务与报告生成完成，不表示全部断言通过。

## 需求工作台

- 状态由团队人工维护，AI 评审不会自动将需求标记为已确认；真实 AI 功能需要配置模型。
- 编辑和版本恢复携带当前版本号，冲突时拒绝覆盖；恢复会生成新版本，不删除历史。
- 关联追踪仅匹配明确的来源标识，不推断旧资产，也不把关联数量当作测试覆盖率。页面最多展示 100 个模块、每类 50 个用例及最近 30 个任务。
- Word / Markdown 导入会创建后台解析任务；上传替换正文前会提示确认。JSON 导入不保留父子层级。
- 回归验证：`.venv/bin/python backend/manage.py test workbench.test_requirements workbench.test_platform --noinput`；`node --test frontend/tests/*.test.mjs`。

## 接口工作台

进入「接口自动化」（`/api-testing`）可通过模块树浏览、筛选和搜索接口，并在多个请求标签间切换。选择父模块会包含子模块接口，搜索支持模块名、接口名、HTTP 方法和路径。请求编辑器提供 HTTP 方法、地址、环境、Headers、Query 参数、JSON Body、Bearer 密钥引用、断言、变量提取与前后置操作。常用断言支持表单编辑及数字、文本、布尔和 null 预期值；复杂对象或数组可切换 JSON 编辑，前后置操作仍使用 JSON 配置。

- 「调试」会先保存当前接口，再通过现有 Worker 执行；结果在页面内展示响应体、响应头、状态码、耗时、断言和变量，也可进入任务详情。
- 结果状态明确区分断言通过、验证失败、请求失败和模拟完成；任务完成本身不表示验证通过。模块导航和状态逻辑的回归测试可使用 Node.js 22.18+ 执行 `node --test frontend/tests/*.test.mjs`。
- 「运行变量」仅用于当前调试，不随接口保存；例如地址 `/users/{{user_id}}` 可使用运行变量 `user_id` 替换路径参数。真实请求仍需配置精确目标白名单；模拟模式不发送 HTTP 请求。
- 「用例与配置」保留批量执行、模块维护、环境、数据库和公共函数管理。OpenAPI 同步与接口导出可直接从工作台访问。
- 草稿在当前页面内按项目暂存；关闭标签或离开工作台时提示未保存修改，刷新或离开后未保存的草稿不会持久化。取消勾选的参数不会发送或保存。

## 数据准备

进入侧边栏“测试管理 → 数据准备”，新建方案并填写字段名、类型和值。支持字符串、整数、小数、布尔值、NULL、嵌套 JSON；可生成 JSON 对象 / 单记录数组，或 SQLite、MySQL、PostgreSQL INSERT。随机字段可选择规则生成，或按填写的示例值随机生成同类数据；支持设置生成数量（1–1000 条），数量大于 1 时 JSON 自动输出数组。SQL 模式需填写表名，表名和字段名使用不超过 63 字符的英文字母、数字和下划线，首字符不能为数字。生成只在本机服务端完成，不调用模型、不连接数据库执行 SQL；敏感字段不可随机生成，须使用服务端密钥引用。

“生成预览”只返回结果；“生成并保存”将字段、生成结果和版本记录存入当前项目数据库。列表支持名称搜索、格式筛选、分页、编辑、删除及 JSON / SQL 文件下载。MySQL 使用 UTF-8 十六进制字符串表达式，避免 SQL 模式引起的反斜杠转义歧义。密钥字段须使用 `{{secret:NAME}}`，生成结果保留引用文本，不读取服务端真实密钥。

接口工作台的 Body、接口 / UI / 流程“执行前数据准备”可选择已保存方案，将字段对象加载为请求体或临时变量。加载会替换当前输入，检查内容后再保存或执行；SQL 文本不会进入自动执行队列。

- `POST /api/entities/prepare_data/`：提交 `project` 和 `config` 生成预览；要求项目编辑权限。
- `/api/entities/`：以 `kind=data_preparation` 保存、查询、编辑与删除方案，沿用项目隔离和版本并发校验。
- `GET /api/entities/{id}/prepared_output/`：下载当前格式结果；可通过 `output_format=json|sql` 指定格式，SQL 下载仍校验表名与字段。
- 回归验证：`.venv/bin/python backend/manage.py test workbench.test_data_preparation workbench.test_platform --noinput`。

### 批量与随机数据准备

在「数据准备 → 新建数据准备」中填写生成数量（1–1000 条）。每个字段可独立开启「随机」：字符串设置 1–256 位长度，生成字母数字组合；整数和小数设置最小值、最大值；布尔值随机输出 true/false。未开启随机的字段沿用填写值，JSON 对象/数组及 NULL 字段保持固定值。敏感字段继续使用服务端密钥引用，不支持随机生成。

多条数据的 JSON 自动输出数组；SQL 每条数据输出一条 INSERT。随机值不保证唯一。点击「生成预览」可重新生成随机批次；随后保存会保留该批次，重复查看、改名及导出不会改变数据。输出体积受现有配置大小限制，提示过大时请减少数量或字段长度。执行前数据准备及接口 Body 的「加载字段数据」载入批次第一条；需要整个批次时复制或下载生成结果。

### 按示例数据随机生成

填写字段值并开启「随机」，选择「按示例随机」（新建字段的默认方式）。示例会保留在方案中，支持生成预览、保存及 JSON / SQL 导出。旧方案保持原有范围 / 长度规则，可手动切换。

- 手机号 `13800138000`：保留 `138` 前三位与 11 位长度。
- 邮箱 `tester01@example.com`：保留域名，用户名中的数字随机变化；无数字的用户名按字符格式随机。
- 编号 `ORD-0001`：保留数字前的前缀与分隔符，随机数字，保留位数及前导零格式。
- 中文姓名（字段名包含 name 或姓名，示例 2–4 个汉字）：按同长度生成常见姓氏及名字组合。其他中文文本按字符类型和长度随机，不推断业务语义。
- 日期支持 `YYYY-MM-DD` / `YYYY/MM/DD`，可带空格或 T 分隔的 `HH:mm:ss`，生成 2000–2035 年内的有效日期。UUID 按相同大小写格式生成。
- 整数和普通十进制小数：保留正负号、整数位数及小数精度（小数最多 12 位；JSON 数字展示可能省略末尾零）。布尔值随机 true / false。

按示例随机须填写有效的 1–256 字符示例。它生成合成测试值，不验证手机号或邮箱是否实际存在，不保证唯一，也不推断地址、身份证等业务有效性。敏感字段仍不可随机。需指定数值上下限或字符串长度时，切换「按范围 / 长度随机」。

## 测试失败分诊（本地规则）

接口 / UI 真实执行结束后，系统使用本地规则生成结构化失败分诊，并保存到任务结果及报告快照。分类包括环境 / 连接、鉴权 / 权限、用例配置、断言差异和待确认；不会将断言差异直接判为产品 Bug，也不会修改用例、放宽断言或自动重试。历史失败任务可单独创建分诊任务，不会重新访问被测系统。

分诊完全在后端本地完成，不调用外部推理服务，不需要服务 URL、密钥或额外容器。结果没有模型概率；复杂根因分析和用例修复仍可使用平台已配置的通用模型能力。

回归：`.venv/bin/python backend/manage.py test workbench.test_triage --noinput`。

## MCP 本地服务与 Worker 恢复

脉知项目的 Playwright MCP 与 Mobile MCP 使用本地 HTTP 服务。若重启电脑，另开两个终端恢复服务，再到「MCP 服务」点击连接测试；配置中的启动命令仅作记录，平台不会自动执行：

```bash
npx -y @playwright/mcp@0.0.76 --isolated --headless --browser chromium --port 8931 --host 127.0.0.1
python3 scripts/start_mobile_mcp.py
```

对应的 Streamable HTTP 地址为 `http://localhost:8931/mcp` 与 `http://localhost:8933/mcp`。Mobile MCP 启动脚本从本机私有文件 `backend/.mobile-mcp-auth` 读取 Bearer token；该文件和加密密钥需保留在本机。本地目标白名单需包含 `localhost:8931,localhost:8933`，更改 `.env` 后重启 Worker。Mobile MCP 的只读 `mobile_list_available_devices` 工具可用于确认设备可见；工具调用仍需平台审批。

停止服务：各终端 Ctrl+C。重启相同服务即可继续访问持久化数据。Worker 中断后，超过 60 秒未更新心跳的任务会恢复入队重新模拟执行；原任务历史保留，旧 Worker 的更新由领取令牌拦截。取消任务不可被 Worker 覆盖。排队状态持续不动时先检查 Worker 是否启动。

## 专用模型服务示例：H2O Lightning Decisions

H2O Lightning Decisions 可在 **模型管理** 中选择独立服务协议，服务根地址填写 `http://192.168.5.195:18741`，模型标识为 `h2oai/h2o-lightning-4b`，无需 API Key。后台 Worker 需要能访问该局域网地址，并将 `192.168.5.195:18741` 加入 `TESTPILOT_ALLOWED_TARGETS`。连接测试调用 `/health`；连接成功后，可从模型卡片的「结构化决策测试」提交 `/v1/systemone` 任务，查看分类、选项概率、分级与服务用量。该服务不是 OpenAI 聊天补全模型，不能用于通用聊天、需求评审、用例生成或录屏图像解析；其明文 HTTP 部署仅应在受控内网访问。

## Docker 部署细节

在仓库根目录运行，需已安装 Docker Desktop / Docker Compose，并按前文配置好 `backend/.env`。前端通过 Node 构建，再由 Nginx 提供页面与同源 API 代理；API 使用 Gunicorn，Worker 独立运行。后台服务共用现有 SQLite、附件和密钥文件。容器异常退出后自动重启，Docker Desktop 本身仍需保持运行。

网页仍为 `http://127.0.0.1:5173`，后台仅映射到 `127.0.0.1:8001`。Nginx 在容器网络中代理 `/api/` 到 `api:8000`，支持 Vue Router 子页面直接打开及刷新，并保留 Cookie / CSRF 校验。可通过 `TESTPILOT_FRONTEND_PORT=5174 TESTPILOT_BACKEND_PORT=8002 docker compose up -d` 更换宿主机端口；更改网页端口时需在 `backend/.env` 的 `CSRF_TRUSTED_ORIGINS` 中补充对应地址，再重启 API。

修改前端源码后运行 `docker compose build frontend && docker compose up -d frontend` 更新页面。需要 Vite 热更新开发时，可先 `docker compose stop frontend`，再执行 `cd frontend && TESTPILOT_API_TARGET=http://127.0.0.1:8001 npm run dev`；同一端口仅启动一种前端服务。

`./backend` 挂载到容器 `/data`，数据库为 `/data/db.sqlite3`、附件为 `/data/media`、开发环境密钥回退文件为 `/data/.secret_key`；`backend/.env` 单独以只读方式挂载。`TESTPILOT_DATA_DIR` 只改变数据目录，未设置时仍使用原本的本机路径。密钥、数据库和附件不会被打包进镜像。停止或重建容器不会删除这些宿主机文件；请勿删除 `backend` 目录。备份时先 `docker compose stop`，一并备份数据库、media、`.env` 与 `.secret_key`，完成后 `docker compose start`。

后台镜像基于按摘要固定的 Selenium 官方镜像，复用其中的 Python 和 Linux Chrome（Chromium 内核），只运行本项目 API / Worker，不启动 Selenium 服务；忽略本机 Chrome 路径配置。容器中的 `localhost` / `127.0.0.1` 指容器自身：若模型、MCP 或测试目标运行在宿主机，需将其服务地址和精确白名单一起改为 `host.docker.internal:端口`，并验证宿主机服务能从 Docker 访问。Gemini 本机代理仍受现有本机地址限制，当前配置不能直接跨容器使用；需要代理时先完成容器网络适配，再执行真实连接测试。连接到 USB 设备的 ADB / Mobile MCP 继续运行在宿主机。

## 数据与安全

- SQLite 数据库：`backend/db.sqlite3`，Django 迁移：`backend/workbench/migrations/`。
- 附件目录：`backend/media/<project_id>/<随机文件名>`，真实路径不返回前端，不开放 `/media/` 静态路由。删除关联记录后文件在数据库事务提交时清除。
- 所有业务数据、执行结果、报告及会话持久化。前端 Pinia 只持有当前会话中的界面状态。
- 凭据只允许写入 `secret` 字段，加密存储；API 仅返回 `has_secret`。修改配置时省略密钥字段表示保留，传空字符串表示清除。服务地址禁止包含账号、密码与查询参数。
- 配置正文、测试内容不是密钥保险箱：请勿在说明、指令或测试文档中填写真实凭据。
- 上传附件通过白名单扩展名和大小校验，并以下载方式返回，`nosniff` 阻止浏览器嗅探为网页。文件不自动执行、解析或导入业务记录。
- 备份：停止服务后一起备份 SQLite、media 目录和 `.env`。恢复到相同结构后执行 migrate。只备份数据库不会包含实际文件。
- 本交付默认绑定本机，Django runserver / Vite 为开发服务器。部署到内网需改用 WSGI 进程管理器和反向代理，将前端 `dist/` 配置为 SPA 回退，同时代理 `/api/`；设置 `DJANGO_DEBUG=false`、稳定 SECRET_KEY、正确 ALLOWED_HOSTS / CSRF_TRUSTED_ORIGINS、HTTPS 与 `SESSION_COOKIE_SECURE=true`。不要让反向代理公开 media 目录。
- URL 白名单按 `host:port` 精确匹配；禁用自动重定向、环境代理与浏览器 Service Worker/WebSocket，浏览器子请求也逐一校验。
- 接口前后置仅支持 `set`、`uuid`、`timestamp`、`concat`；UI 仅支持白名单步骤。Skills 只安装声明式指令，不运行远程 Python、Node 或 Shell。
- MCP 真实工具调用保存工具名和参数，并由项目所有者逐次审批。密钥、Authorization、Cookie 和常见 Token 字段在任务结果与日志中脱敏。
- SQLite + 单 Worker 面向本地/小团队；大量并发生产测试可迁移 PostgreSQL + 外部任务队列。当前版本不包含移动设备执行器、定时调度或分布式执行节点。

## API 数据格式示例

列表支持 `project`、`search`、`page`（每页 10 条）；资源/资产额外支持 `kind`，资产/报告支持 `status`。返回 `{count,next,previous,results}`。列表、修改、删除和下载均按项目权限隔离。

创建用例示例：

```json
{
  "project": 1,
  "kind": "case",
  "name": "正常登录",
  "priority": "P0",
  "status": "ready",
  "data": {
    "steps": [{"action": "提交正确账号和密码", "expected": "进入工作台"}],
    "simulate_result": "passed"
  }
}
```

计划/流程 `data` 为 `{"case_ids":[1,2,3],"agent_id":可选AgentID}`（未选择时省略 agent_id 或传 null）。文档 `data` 为 `{"content":"文档正文"}`。Agent `settings.resource_ids` 指向同项目的资源。输入引用、项目 ID、状态、步骤由后端校验。
