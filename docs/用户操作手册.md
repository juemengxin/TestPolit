## 1. 快速上手

### 1.1 推荐操作流程

| 顺序 | 操作 | 完成标志 |
| --- | --- | --- |
| 1 | 登录，选择或创建项目 | 顶部显示正确项目名称 |
| 2 | 配置模型并测试连接；按需配置 Skill、MCP、Agent | 对应连接任务成功，资源已启用 |
| 3 | 导入需求并检查解析正文 | 需求正文与文档内容一致 |
| 4 | 评审需求，拆分模块并确认规则 | 功能、边界和待确认事项明确 |
| 5 | 选择模块生成接口或 App/Web 用例 | 结果写入对应测试资产列表 |
| 6 | 准备环境、测试数据、执行步骤和断言 | 用例不再缺少必要执行配置 |
| 7 | 先单例调试，再批量或按流程运行 | 任务产生实际执行结果 |
| 8 | 查看报告、分析失败并复测 | 每项结论都有日志、断言或执行证据 |

### 1.2 三种结果应如何理解

| 标识 | 含义 | 使用方法 |
| --- | --- | --- |
| 模拟模式 | 相应任务不执行真实模型或目标服务调用 | 用于熟悉平台流程，不能作为真实测试通过证据 |
| 真实执行 | 按所选配置访问真实模型、接口、浏览器或设备 | 检查连接、环境和用例结果后判断是否通过 |
| 本地处理 | 文档解析、数据生成等本地操作 | 根据具体任务结果检查，不代表执行了被测系统 |

资源连接成功只证明本次连接测试成功；任务“已完成”只表示流程结束。两者均不等于全部测试通过。

## 2. 登录、项目和权限

### 2.1 登录与退出

1. 打开平台网页，输入管理员分配的账号和密码。
2. 登录后确认右上方的当前项目。
3. 使用结束后，通过右上角用户菜单退出登录。

不要在本手册、需求正文或公共数据中记录登录密码。没有账号时联系系统管理员。

### 2.2 创建项目和管理成员

1. 进入 **项目管理**，单击 **创建项目**。
2. 填写名称、唯一标识和描述，保存后选择该项目。
3. 在成员管理中添加已有用户，并分配角色。

项目标识应保持稳定，例如 `MALL`。删除项目前先确认关联资产和备份；项目删除会影响其关联数据。

### 2.3 项目隔离与角色

| 角色 | 主要权限 |
| --- | --- |
| 系统超级管理员 | 管理系统、用户、组织及全部项目 |
| 项目所有者 | 管理项目数据和成员，审批项目 MCP 工具调用 |
| 编辑者 | 维护项目配置与测试资产，提交和处理权限范围内的任务 |
| 观察者 | 查看、筛选、下载和导出有权访问的项目数据 |

权限由后端强制校验。按钮可见不代表能绕过权限；出现 403 时请检查项目角色。

顶部切换项目后，列表和可选资源会随项目改变。切换前保存当前输入，避免丢失未保存草稿。

### 2.4 主题和语言

通过顶部主题按钮切换深色/浅色界面，通过语言按钮切换中英文。部分业务正文、模型输出和技术字段保持原文。

## 3. 模型、Skill、MCP 与 Agent

### 3.1 模型配置

入口：**能力中心 → 模型管理**。

1. 新建模型，填写名称、服务地址和模型标识。
2. 在 **API Key** 专用字段填写凭据；不要将其写入普通配置、日志或 Prompt。
3. 保存并启用资源，执行 **连接测试 → 模型 / MCP 连接**。
4. 到任务详情检查结果，成功后再用于真实评审或用例生成。

DeepSeek、千问、Gemini 等服务应使用所选模型实际支持的兼容地址和模型标识。不同服务的 Key 不通用；不要把文档页面地址当作 API 地址。

密钥加密保存，不明文返回前端。编辑时留空表示保留原密钥，只有显式清除才移除。嵌入模型、Reranker 需要分别执行相应连接测试。

#### H2O Lightning Decisions

脉知项目已预置 **H2O Lightning 4B** 模型资源，服务地址为 `http://192.168.5.195:18741`。该服务采用 `/health` 和 `/v1/systemone` 结构化决策协议，不兼容通用 OpenAI 聊天补全，因此不能选作需求评审、用例生成、Agent 聊天或视频解析模型。

在模型卡片执行 **连接测试 → 模型 / MCP 连接** 检查健康状态；随后可选择 **结构化决策测试**，输入上下文与命名问题 JSON，提交后在任务详情查看答案、概率与用量。Worker 只能访问配置在 `TESTPILOT_ALLOWED_TARGETS` 中的精确主机及端口；部署前需确认 Worker 到该内网地址的路由、防火墙与服务状态。当前接口为无 API Key 的明文 HTTP 服务，仅在可信内网使用；连接未验证前资源会显示未验证状态。不要将密码、令牌或个人敏感信息放入决策上下文。

### 3.2 Skill 管理与技能库

- **Skill 管理**：维护技能名称、说明和指令内容；检查技能是否启用。
- **Skills 技能库**：配置可信来源、查看技能清单、安装后到 Skill 管理核对内容。
- **使用 Skill**：在 Agent 中关联，或在 AI 工作室选择技能。`ui-testcase-generation` 可通过资源卡片上的 **使用 Skill 生成用例** 进入对应流程。

Skill 用于约束任务方法和输出规范，不代表外部设备、浏览器或服务已配置完成。平台使用声明式技能内容，不会因为文档中写了命令就自动执行任意 Shell、Python 或 Node 代码。

### 3.3 MCP 服务

入口：**能力中心 → MCP 服务**。

1. 创建服务，填写 Streamable HTTP 地址、凭据及说明。
2. 启动实际 MCP 服务，再保存、启用并测试连接。
3. 将服务关联至所需 Agent 或执行配置。
4. 工具调用进入待审批时，项目所有者在 **任务中心** 检查服务、工具名称和参数，再批准或拒绝。

Playwright MCP 用于浏览器相关工具，Mobile MCP 用于设备相关工具。保存服务配置不会自动启动外部进程；连接成功也不等于工具调用已获审批。

### 3.4 Agent 管理

入口：**能力中心 → Agent 管理**。

1. 新建 Agent，填写名称、用途和系统指令。
2. 关联当前项目的模型、Skill 和 MCP 能力。
3. 保存后，在 **Agent 对话** 或相关任务中选择该 Agent。

建议按职责配置需求评审、用例设计、接口配置修复、Web 测试、App 测试等 Agent。Agent 的名称只是用途说明，实际能力由关联资源、工具权限和运行环境决定。

## 4. 需求管理与评审

入口：**智能中心 → 需求管理**。

### 4.1 新建或导入需求

- **新建需求**：填写标题、正文、负责人、优先级、标签和验收标准等信息，保存。
- **导入文档**：选择 `.md`、`.doc` 或 `.docx` 文件，提交后等待后台解析，单文件不超过 10 MB。
- **导入 JSON**：使用需求目录下方入口导入平台需求数组。该方式创建独立需求，不恢复父子层级。

解析完成后核对标题、正文、表格文字和规则是否完整。旧版 `.doc` 无法解析时，可转换为 `.docx` 后重试。任务未结束前不要重复上传相同文件。

### 4.2 替换文档、版本对照与恢复

1. 选择现有需求，打开 **原始附件**。
2. 单击 **上传 Word / Markdown 并更新正文**。
3. 确认替换，等待解析任务完成，检查新正文。
4. 在 **版本对照** 查看历史与当前内容；需要回退时选择 **恢复为新版本**。

替换和恢复均保留历史记录。多人同时编辑出现版本冲突时，重新加载最新版本后再修改，避免覆盖他人变更。

### 4.3 真实 AI 评审

1. 选择有正文的需求，单击 **AI 评审**。
2. 在 AI 工作室选择真实模式和目标模型，例如当前项目配置的千问。
3. 按需关联 Agent、Skill、知识库，补充评审关注点。
4. 提交后到任务中心查看遗漏、歧义、规则冲突、边界和测试关注点。
5. 由负责人确认评审结论并维护需求状态。

AI 评审不会自动将需求标记为“已确认”。文档更新后，应针对新版本重新评审，历史评审不代表覆盖新正文。

### 4.4 先拆模块，再生成用例

1. 使用 **拆分子需求** 分析功能层级和各节点规则。
2. 检查前置条件、操作流程、校验规则、异常提示、特殊逻辑和待确认项。
3. 使用 **同步功能模块**，按需求正文的 Markdown 标题建立功能模块关联；检查模块名称和归属。
4. 进入 **生成模块用例**，选择对应模块或全部模块后生成。

拆分子需求属于 AI 分析；同步功能模块依据正文结构建立关联。同步不会凭空补全没有写入正文的业务规则。AI 产物需要应用到资产后才会出现在相应资产列表。

### 4.5 关联追踪

在 **关联追踪** 查看功能模块、关联用例及评审/生成任务，检查源版本。源版本与当前需求不一致时，应确认是否需要更新用例。

关联数量不是测试覆盖率。没有来源标识的历史资产不会自动推断关联；完整列表以对应管理页面为准。

## 5. 知识库

1. 进入 **知识库**，创建知识库并设置分块及模型配置。
2. 在知识文档页签上传资料，等待解析、分块及相应向量化任务结束。
3. 使用 **检索** 输入业务问题，检查返回片段和来源。
4. 在 AI 工作室选择知识库，为评审、用例生成和对话补充上下文。

可保存产品说明、业务规则、接口契约和团队规范。采用本地处理与真实嵌入模型时，其检索能力和服务依赖不同，应以当前配置和任务结果为准。知识库中不要保存真实凭据。

## 6. AI 用例生成与模板

### 6.1 按需求和模块生成

1. 从需求详情的 **生成模块用例** 进入，或打开 **AI 智能工作室** 选择来源需求。
2. 选择真实模型；按需关联 Agent、Skill、知识库和模板。
3. 检查功能拆分结果，选择目标模块或全部模块。
4. 选择生成目标：接口用例，或 UI 用例中的 **Web / App**。
5. 描述范围、测试关注点和验收要求，选择是否自动写入资产。
6. 提交任务，完成后检查结果；未自动写入的结果，通过 **应用到资产** 保存。
7. 到 **接口自动化** 或 **UI 自动化** 的对应列表检查新增用例。

模块用例按需求规则覆盖生成，不设置“每模块固定生成条数”。实际结果仍受文档内容、模型上下文和执行资源限制；任务报错或结果不完整时，应检查日志并分模块处理。

### 6.2 用例质量检查

| 检查项 | 要求 |
| --- | --- |
| 来源 | 对应正确需求版本和业务模块 |
| 粒度 | 每条用例聚焦一个可独立验证的场景或规则 |
| 覆盖 | 正常、异常、边界、规则优先级、特殊及兼容场景 |
| 步骤 | 前置条件明确，操作可执行，预期可验证 |
| 执行条件 | 环境、数据、定位器、鉴权和依赖变量已补齐 |
| 结论 | 不把模拟产物或未验证草稿视为已执行通过 |

### 6.3 模板、优化与 Agent 对话

- **模板与策略**：维护 Prompt、用例模板和生成策略，统一团队输出结构和覆盖维度。
- **用例优化 / AI 编辑修复**：选择已有资产，说明需要补全或修复的内容，检查结果后应用。
- **Agent 对话**：选择 Agent 和上下文提问，查看任务历史、引用、Token 用量及工具调用过程。

自动生成的用例可能仍需定位器、设备和数据映射，完成设计不代表已经具备自动执行条件。

## 7. 数据准备：固定、随机与按示例生成

入口：**测试管理 → 数据准备**。

### 7.1 新建与生成

1. 单击 **新建数据准备**，填写方案名称。
2. 设置 **生成数量**，支持 1–1000 条。
3. 选择 JSON 或 SQL INSERT；SQL 还需填写目标表名并选择方言。
4. 使用 **添加字段**，逐行填写字段名、类型和值。
5. 根据字段用途选择固定值、按示例随机或按范围 / 长度随机。
6. 单击 **生成预览** 检查结果。
7. 单击 **生成并保存** 保存到当前项目；在列表中编辑、筛选或下载结果。

预览不会保存方案。保存后可在刷新页面或重启服务后恢复；列表显示数据条数、字段数、格式和版本。

### 7.2 字段类型

| 类型 | 填写示例 | 结果 |
| --- | --- | --- |
| 字符串 | `ORD-0001` | 保留文本；长编号建议使用此类型 |
| 整数 | `18` | JSON 整数 |
| 小数 | `12.50` | JSON 数字，显示时可能省略末尾零 |
| 布尔值 | `true` / `false` | JSON 布尔值 |
| NULL | 无须填写 | JSON null / SQL NULL |
| JSON 对象或数组 | `{"tags":["new"]}` | 嵌套结构 |

一个方案支持 1–200 个字段，字段名不能重复。JSON 对象/数组和 NULL 字段保持固定值，不开启随机。

### 7.3 按填写的示例随机生成

新建字段默认使用此随机方式；旧方案可能仍是范围 / 长度规则，可手动切换。

1. 填写字段名和正确类型。
2. 开启该行 **随机**，选择 **按示例随机**。
3. 在 **示例数据** 中填写有效示例，长度为 1–256 字符。
4. 设置生成数量后单击 **生成预览**。

| 数据类别 | 示例 | 生成规则 |
| --- | --- | --- |
| 手机号 | `13800138000` | 保留前三位和 11 位长度，随机后八位 |
| 邮箱 | `tester01@example.com` | 保留域名；用户名数字按位随机；无数字时按字符格式随机 |
| 编号 | `ORD-0001` | 保留首个数字前的前缀与分隔符，数字按位随机 |
| 中文姓名 | 字段名 `full_name`，示例 `张三` | 字段名含 name 或姓名、示例为 2–4 个汉字时，生成同长度姓氏和名字组合 |
| 普通中文文本 | `测试内容` | 按汉字类型和长度随机，不推断业务语义 |
| 日期 | `2024-02-29` / `2024/02/29` | 保留分隔格式，生成 2000–2035 年内的有效日期 |
| 日期时间 | `2024-02-29 13:05:09` | 支持空格或 T 分隔及 HH:mm:ss，生成有效日期时间 |
| UUID | `123e4567-e89b-12d3-a456-426614174000` | 生成 UUID v4，保持相应大小写格式 |
| 整数、小数 | `-18`、`12.50` | 保留符号、整数位数及相应小数精度；小数示例最多 12 位小数 |
| 布尔值 | `true` | 随机 true 或 false |

以上为合成测试数据：不保证唯一，不验证号码、邮箱是否实际存在，不推断身份证、地址等业务合法性。固定不变的字段请关闭随机。

### 7.4 按范围 / 长度随机

开启随机后，切换为 **按范围 / 长度随机**：

- 字符串：设置 1–256 位长度，生成英文字母和数字组合。
- 整数：设置整数最小值和最大值。
- 小数：设置数值最小值和最大值。
- 布尔值：随机生成 true 或 false。

数值范围须在 ±1,000,000,000 以内，最小值不得大于最大值。此方式不依据示例格式。

### 7.5 示例操作

建立一个 3 条记录的 JSON 方案：

| 字段名 | 类型 | 示例值 | 随机方式 |
| --- | --- | --- | --- |
| phone | 字符串 | 13800138000 | 按示例随机 |
| order_no | 字符串 | ORD-0001 | 按示例随机 |
| enabled | 布尔值 | true | 关闭随机，固定值 |

预览会得到如下结构，实际随机值每批不同：

```json
[
  {"phone":"13846774166","order_no":"ORD-0258","enabled":true},
  {"phone":"13851514444","order_no":"ORD-6143","enabled":true},
  {"phone":"13849509856","order_no":"ORD-7806","enabled":true}
]
```

### 7.6 输出、保存与应用

| 操作 | 行为 |
| --- | --- |
| JSON 单条 | 可选择对象或数组 |
| JSON 多条 | 自动使用数组 |
| SQL | 支持 SQLite、MySQL、PostgreSQL，每条数据生成一条 INSERT |
| 再次生成预览 | 随机字段生成新批次 |
| 预览后保存 | 保留该批次；重复查看、改名、导出保持结果一致 |
| 下载结果 | 下载当前方案的 JSON 或 SQL 文件 |
| 加载字段数据 | 将已保存批次的**第一条**加载为字段对象，不会自动遍历整批 |

可在接口工作台 **Body**，或接口 / UI / 流程的 **执行前数据准备** 中选择方案并单击 **加载字段数据**。加载会替换当前输入，核对后再保存或执行。需要整个批次时复制或下载生成结果。

SQL 只生成文本，不连接数据库执行。表名和 SQL 字段名须以英文字母或下划线开头，只含英文字母、数字和下划线，最多 63 字符。MySQL 字符串采用 UTF-8 十六进制表达式，是正常输出格式。

敏感字段不能随机生成，须使用 `{{secret:NAME}}` 引用；生成过程不读取真实密钥。超过 JSON 安全整数范围的编号应选择字符串。结果过大时请减少数量、字段或字段长度。

## 8. 接口自动化

### 8.1 工作台与配置管理

入口：**接口自动化**。工作台可按模块、接口名称、方法和路径查找接口，多标签编辑请求。

- 工作台用于请求配置和单例调试。
- **批量执行 / 环境 / 公共函数** 进入接口用例与配置管理。
- **同步 OpenAPI** 导入接口定义；检查同步后的名称、路径和参数，再补充业务数据和断言。

### 8.2 请求配置

| 配置 | 填写内容 |
| --- | --- |
| 方法和地址 | GET、POST 等方法；完整 URL 或环境基址对应的相对路径 |
| 环境 | base_url、全局 Headers 和环境变量 |
| Headers | 请求头；敏感值使用服务端引用 |
| Params | Query 参数，如 page、page_size |
| Body | JSON 对象；GET / HEAD 不发送请求体 |
| Auth | 用密钥名称设置 Bearer Header |
| 运行变量 | 仅本次调试使用，不随接口保存 |
| 断言 | 状态码、业务字段及所需响应校验 |
| 提取变量 | 从响应 JSON 路径读取值，例如 data.id |
| 前置 / 后置 | 平台支持的 set、uuid、timestamp、concat 声明式操作 |

业务变量使用 `{{user_id}}`，敏感引用使用 `{{secret:API_TOKEN}}`。服务端对应设置 `TESTPILOT_SECRET_API_TOKEN`。不要把 Key 直接拼进 URL。

### 8.3 调试与执行前数据准备

1. 选择接口和环境，补齐请求参数、断言和依赖变量。
2. Body 可加载已保存数据准备方案；GET 参数仍应填入 Params。
3. 执行前数据准备中，按需要填写准备请求的地址、路径、参数及临时变量，检查所用测试环境。
4. 单击 **调试**；平台先保存当前接口，再提交后台任务。
5. 查看响应体、响应头、请求信息、验证结果及运行变量结果。
6. 单例通过后，在配置管理页选择用例进行批量运行。

真实目标必须在管理员配置的精确 `host:port` 白名单中。HTTP 200 只代表 HTTP 层响应成功，仍应检查业务状态和断言。

### 8.4 数据库校验与公共函数

数据库配置用于平台支持的 SQLite 只读查询与断言，不用于执行 INSERT 或修改业务数据。公共函数使用平台支持的声明式动作；不要填写任意可执行脚本。

### 8.5 AI 编辑和修复

1. 在工作台选择接口，单击 **AI 编辑 / 修复**；也可从资产记录的更多菜单进入。
2. 描述参数、Header、环境、数据库校验、断言、依赖变量等问题。
3. 检查带入的接口及关联配置，选择真实模型并提交。
4. 查看变更和校验结果，应用后重新执行验证。

工作台未保存的修改会先保存再进入 AI 流程。配置结构、项目归属或版本冲突校验失败时，不会强行应用过期修改。AI 修改配置不代表目标系统缺陷已修复。

## 9. UI 自动化：Web 与 App

入口：**UI 自动化**。通过 **Web 用例 / App 用例** 区分平台，列表按最近更新时间倒序查看。

### 9.1 认识四类配置

| 配置 | 用途 | 应填写什么 |
| --- | --- | --- |
| 执行机 | 确认执行资源、连接设备及连接状态 | 本地执行资源；App 所用设备信息 |
| UI 环境 | 配置测试访问环境与变量 | Web base_url、超时、环境变量 |
| 页面对象 | 复用页面地址和元素定位器 | 登录页地址、用户名框、登录按钮等稳定定位器 |
| 公共数据 | 共享测试变量和 App/Web 执行配置 | 非敏感变量、程序 URL，或 App 名称、包名、设备 ID、Mobile MCP |

连接测试显示机型或设备成功，只证明设备可识别；需要真实执行来验证用例。

### 9.2 配置 Web 用例

1. 选择 **Web 用例**，新建或编辑目标用例。
2. 配置程序 URL、Chromium 浏览器、环境及必要测试数据。
3. 编排操作、元素定位、输入内容、等待条件和预期断言。
4. 使用页面对象复用稳定定位器，保存用例。
5. 先执行一条，查看浏览器实际结果，再扩大执行范围。

Web 用例可使用本地 Playwright / Chromium 执行；Agent 通过 Playwright MCP 调用工具时，还需完成相应服务关联和审批。两种入口应分别检查其运行配置。

### 9.3 Android App 操作录制

1. 进入 **UI 自动化 → App 用例 → 录制**，选择项目中的真实 **Mobile MCP** 服务，点击检测设备并选择在线 Android 测试机，再输入 Android 应用包名（如 `com.example.app`）。iOS 设备暂不支持当前 App 用例执行器。
2. 点击 **启动应用并开始录制**。应用启动和每个录制操作由后台 Worker 排队执行；等待状态结束、设备截图刷新后再继续。点击屏幕、输入文本、设备按键、方向滑动、精确文本断言和 0–30 秒等待均可录制。手机上直接触摸不会自动采集。
3. 点击结束并填写用例名。用例保存到当前项目的 **App 用例**，初始状态为“未验证”。请复核设备坐标，补充测试数据及断言后再执行。
4. 勾选**敏感输入**时，输入内容仅加密排队传送到设备；步骤只保存为 `{{recorded_secret}}` 等变量引用，不会出现在用例、任务日志或报错中。执行时在准备数据中提供同名变量。取消录制不会撤销手机上已经发生的操作。
5. 后台操作失败、超时或 Worker 中断后，操作结果可能不确定。页面不会自动重放该操作；刷新设备画面检查实际状态，再决定是否继续或取消。

管理员需连接已授权 USB 调试的 Android 设备，启动仓库 `scripts/start_mobile_mcp.py`，并将 MCP 地址设为 `http://host.docker.internal:8933/mcp`，在 `TESTPILOT_ALLOWED_TARGETS` 中加入精确目标 `host.docker.internal:8933`，然后重启 API 和 Worker。Mobile MCP 的日志输出会被关闭，因为第三方调试日志可能写入用户输入文本。截图、设备画面和录制会话受项目权限校验。

### 9.3 从录制生成用例并检查回放稳定性

1. 在 **UI 自动化 → 录制** 进入 Web 录制工作台，选择项目并填写目标 URL。管理员需提前将目标主机和端口及必要依赖域名加入 `TESTPILOT_ALLOWED_TARGETS`。
2. 点击 **开始录制**，在平台显示的 Chromium 画面中操作。支持点击、输入、按键、勾选及单选下拉框；连续输入会合并为一步，页面显示采集步骤数。刷新工作台后可恢复自己的会话。
3. 填写可选的用例名称，点击 **结束并生成用例**，系统保存到当前录制所属项目的 **Web 用例** 列表，标记为“未验证”。**取消录制** 关闭浏览器且不创建用例；服务重启会结束未保存的会话。
4. 打开生成的用例，补充预期结果、断言、测试数据和前置条件。录制不代表测试通过，也不能推断业务预期。识别出的敏感输入替换为 `{{recorded_secret}}`，需通过公共数据或执行前数据准备配置。录制时请使用测试账号。
5. 选择 **真实执行**，设定 **重复回放次数**（1–20）和 **卡顿阈值**（500–60000 毫秒）后运行。每一轮使用独立浏览器上下文。
6. 任务详情按轮展示通过/失败、稳定率、慢步骤、页面 JavaScript 异常，并保存截图、视频和 Trace。模拟模式不会启动浏览器，也不产生真实稳定性结论。

录制范围与限制：

- Docker 方式启动后提供平台内 Chromium，桌面画面通过平台 `/recorder/` 代理提供，页面资源和 WebSocket 连接均验证登录身份及项目编辑权限；不直接开放 7900 端口。同一服务一次仅允许一个录制会话，只有该会话的创建者且仍有项目编辑权限才能操作。停止或取消时会关闭画面连接，避免遗留连接看到下一个会话。
- 每次最多录制 30 分钟、100 个步骤；超限会显示错误，不会静默截断后生成用例。iframe、新窗口、文件上传、拖拽、多选下拉等需手动配置，检测到时会显示提示并写入用例备注。
- 平台直接采集手动操作，不依赖 Trace 推断用户手势。临时 Trace 和采集文件在结束、取消或检测到进程异常后清理；数据库中的用例和版本记录持久化保存。
- 已有 Trace 可在同一页面使用 **导入已有 Playwright Trace** 转成用例。Trace 必须包含 Playwright 的导航和定位器调用记录；单纯的视频或手动操作截图不能直接还原为可执行步骤。上传 ZIP 不超过 12 MB（默认网关限制）。

管理员验证命令：`docker compose exec api python manage.py test workbench.test_recording workbench.test_platform --noinput`。


### 9.4 配置 App 用例

1. 确认设备连接，并启动可访问设备的 Mobile MCP 服务。
2. 在 **App 用例** 中配置 App 名称、Android 包名、设备 ID 和已启用的真实 Mobile MCP 资源。
3. 检查操作步骤、元素或坐标、输入数据和断言适用于当前设备。
4. 保存后单例运行，核对应用是否启动、步骤是否执行以及预期是否满足。

未发现设备、包名错误或 MCP 不可达时，应先修复环境。设备连接状态不能替代 App 运行结果。

### 9.4 应用公共执行配置

1. 到 **公共数据** 新建 **Web 执行配置** 或 **App 执行配置**。
2. 填写对应 URL / 浏览器或应用 / 包名 / 设备 / MCP 信息，以及公共测试变量。
3. 回用例列表，勾选同平台用例，单击 **应用公共配置**。
4. 选择配置并确认，检查目标用例更新后的执行信息。

App 与 Web 配置应分别维护。共用数据不要直接放真实密码、令牌或一次性验证码。

### 9.5 草稿、待配置与未验证

| 标识 | 含义 | 下一步 |
| --- | --- | --- |
| 设计草稿 | 以自然语言描述业务操作 | 配置资源并转换、补充可执行步骤 |
| 待配置执行 | 缺少必要执行条件或步骤映射 | 打开用例补齐配置，不能直接视为可运行 |
| 未验证 | 步骤结构已生成，但尚未完成真实目标验证 | 实际运行并检查步骤与断言 |

可选择用例，使用 **转为可执行步骤** 转换可识别操作。无法可靠映射的定位、业务状态和数据仍需补充，不能通过修改状态文字代替真实验证。

### 9.6 批量执行与 UI 测试流程

- **批量执行**：选择同平台、配置完整的用例，选择模式和环境后提交。
- **UI 测试流程**：新建流程，选择平台及用例，用上移/下移调整顺序，配置环境，检查后将草稿改为就绪并执行。

流程中的用例必须平台一致，且具备运行条件。删除被流程引用的用例前，应先从流程中移除关联。

执行过程中去任务中心查看进度；结束后查看日志、截图、视频和 Trace。定位失败时依次检查页面状态、登录、弹窗、定位器、等待条件和环境地址。

## 10. 测试资产、计划、套件与流程

### 10.1 文档和功能模块

- **测试文档**：保存测试说明、规范和参考资料。
- **功能模块**：在 UI 自动化及关联管理入口维护模块层级和归属，用于组织用例。
- 当前用例工作台以接口、Web 和 App 分类；历史 `/assets/case` 入口会跳转到 UI 自动化。

### 10.2 计划、套件和流程的区别

| 类型 | 适用场景 |
| --- | --- |
| 测试计划 | 为某次迭代或版本组织测试范围 |
| 测试套件 | 保存可重复使用的用例集合 |
| 测试流程 | 编排业务验证顺序 |
| UI 测试流程 | 串行运行同一平台的 UI 用例，位于 UI 自动化中 |

创建时填写名称并选择用例，核对范围与顺序。具体执行入口和配置要求以该资产页面提供的操作为准。

### 10.3 用例导入导出

1. 在目标用例列表选择导入入口，按平台数据结构导入；导入前检查类型、步骤和模块归属。
2. 通过 **导出** 选择 JSON 或 **Excel（.xlsx）**。
3. 导出应用当前项目、类型、搜索及 App/Web 平台筛选，包含全部符合条件的记录，不局限于当前分页。

Excel 包含名称、平台、前置条件、步骤、预期、版本等信息；复杂配置以 JSON 文本保存。Excel 导出不代表支持 Excel 原样回导；重复导入可能创建重复记录。

## 11. 任务中心与失败分析

入口：**任务中心**。文档解析、AI 生成、评审、连接测试、接口和 UI 执行等任务均在此追踪。

### 11.1 状态说明

| 状态 | 含义与操作 |
| --- | --- |
| 排队中 | 等待 Worker；持续无变化时检查 Worker |
| 待审批 | 等待所有者检查 MCP 工具及参数 |
| 运行中 | 查看进度与日志，避免重复提交 |
| 已完成 | 流程结束；继续检查结果是否通过 |
| 失败 | 查看错误、日志和输入配置，修复后重新提交 |
| 已取消 | 已终止；重新执行需要再次提交 |

任务在后台处理，可离开页面后再查看。关闭网页不会把已提交任务变成同步请求。

### 11.2 检查结果与应用资产

打开详情，检查 **执行结果、流程与日志、输入与引用、截图 / 视频 / Trace**。

生成任务未自动写入时，结果通过校验后单击 **应用到资产**。设计任务可导出 Markdown，其他导出以页面入口为准。任务输入快照用于追踪当时配置，不应将修改后的资产当作旧任务的实际输入。

### 11.3 分析失败、修复并复测

1. 在真实接口 / UI 任务中选择失败用例，单击 **分析此失败用例** 或 **AI 失败分析**。
2. 选择真实模型，检查失败响应、日志、截图及输入数据。
3. 判断属于用例配置、环境问题还是被测产品问题。
4. 若是用例问题，检查建议变更后应用；存在版本冲突时先重新加载资产。
5. 若分析结果提供修复并重跑操作，检查目标后提交；否则回列表重新运行。
6. 对照新旧任务与报告确认修复效果，保留原始失败证据。

不要为了获得通过结果而删除有效断言或放宽验收规则。模型建议本身不构成问题已修复的证据。

### 11.4 测试失败分诊

真实接口 / UI 执行结束后，任务和报告会保存「测试失败分诊」；接口工作台的调试结果也有「失败分诊」页签。历史已完成的真实失败执行可在任务详情单击 **失败分诊**，在后台创建新任务，不会重新访问被测系统。

| 处理方向 | 建议操作 |
| --- | --- |
| 环境 / 连接 | 检查网络、服务、目标白名单及设备连接 |
| 鉴权 / 权限 | 检查账号权限、凭据引用和登录状态 |
| 用例配置 | 核对断言、定位器和依赖变量，必要时使用 AI 编辑修复 |
| 断言差异 | 对照需求和真实结果判断，不直接归为产品 Bug |
| 待确认 | 查看日志、截图、Trace，补充证据后再分析 |

分诊仅使用后端本地规则，不调用外部推理服务，也不需要单独配置模型服务。页面会标明处理方向来自本地规则，不显示模型概率。复杂根因分析和用例修复仍可通过平台已配置的通用模型能力单独发起。

分诊不修改用例、断言或执行结论，也不会自动重试。确认需要修复后，再进入 AI 失败分析并按版本校验流程应用和复测。历史任务中已保存的模型分析快照会保留，但新分诊不会再调用该服务。

## 12. 测试报告与执行产物

入口：**测试管理 → 测试报告**，或任务详情中的 **查看测试报告**。

### 12.1 查看报告

1. 按项目、名称、状态和结果筛选报告。
2. 查看执行模式、时间、总数、通过、失败、跳过及通过率。
3. 展开失败用例，核对步骤预期、实际结果、耗时和错误。
4. 查看执行日志、历史和输入快照，确认环境及资产版本。

报告保存执行结果与历史，刷新或重启后可恢复。数据准备预览、文档解析等任务不等于测试执行，不应期待每种任务都产生测试报告。

### 12.2 截图、视频和 Trace

- 在任务的 **截图 / 视频 / Trace** 或报告的 **截图与附件** 查看产物。
- 截图可预览和放大，视频可直接播放，其他文件可下载。
- Trace 下载后使用兼容的 Playwright Trace 查看工具分析 Web 执行。

附件须经过项目权限校验。未采集、执行未启动或对应执行器不提供的产物不会凭空生成；App 与 Web 的附件类型可能不同。

### 12.3 导出与删除

通过报告页面导出 JSON 结构化结果；任务导出和用例 Excel 导出属于不同入口。运行中的报告不能直接删除，应先取消并等待结束。删除前确认审计和留存要求。

## 13. 团队与系统管理

入口：**系统管理**，可见范围取决于账号权限。

- **用户和组织**：由超级管理员维护账号、组织成员和项目关联。
- **项目访问密钥**：创建后完整值只显示一次，应立即按组织要求保存；后续可撤销。密钥只用于允许的项目和权限范围。
- **操作审计**：查询关键写操作的用户、项目、时间及目标。
- **全局配置**：管理日志保留、版本提示和默认知识库等设置；知识库仍受项目权限限制。

API Key 不是登录密码。资源 API Key、项目访问密钥与业务测试密钥用途不同，不能互换。发现泄露后撤销或轮换对应凭据。

## 14. 常见问题

| 现象 | 排查步骤 |
| --- | --- |
| 身份认证信息未提供 | 重新登录；保持同一访问主机，避免混用 localhost 和 127.0.0.1；检查 Cookie 和 API 代理 |
| 无权限 / 403 | 检查当前项目、成员资格及角色；联系项目所有者 |
| 列表没有数据 | 检查当前项目、App/Web 页签、搜索条件和筛选条件 |
| 导入需求一直解析中 | 打开解析任务查看是否排队或失败；检查 Worker 和文档格式；不要反复重复导入 |
| 模型连接失败 / ConnectError | 检查服务地址、模型名、API Key、白名单，以及 Worker 所在环境的网络可达性 |
| 模型超时 | 查看任务日志；确认服务可用，将大需求按模块处理；连接测试成功不能保证大任务不会超时 |
| 容器无法连接本机 MCP / 模型 | 容器内 127.0.0.1 指向容器自身；让管理员检查 host.docker.internal、服务监听地址和白名单 |
| 提示敏感配置使用 secret 引用 | 改为 `{{secret:NAME}}`，由管理员设置对应 `TESTPILOT_SECRET_NAME`，不要填明文 |
| AI 用例未出现在列表 | 查看生成任务是否成功、是否应用到资产，以及目标项目和 App/Web 平台 |
| UI 用例待配置执行 | 补齐环境、URL/包名、设备/MCP、步骤定位和测试数据 |
| 任务完成但有失败 | 检查用例及断言，完成状态不表示全通过 |
| 没有测试报告 | 确认是测试执行任务；检查执行结果、报告关联和后台日志，其他处理任务不一定产生测试报告 |
| 没有截图或视频 | 确认实际执行是否启动、是否采集该类型附件及是否有访问权限 |
| 数据随机后格式不对 | 确认选择了按示例随机而非按范围 / 长度随机，检查类型和示例是否受支持 |
| 生成数据重复 | 随机不保证唯一；需要唯一性时对生成结果另做业务校验 |
| 加载方案只出现一条 | 加载字段数据按设计只取批次第一条；整批请复制或下载生成结果 |
| 数据生成提示过大 | 减少生成数量、字段数量或字段长度，单次 1000 条仍受结果体积限制 |
| 保存出现版本冲突 | 重新加载最新版本，核对他人改动后再次保存 |

## 15. 管理员维护速查

以下命令均在项目根目录执行；安装和环境变量的完整说明见项目 README。普通用户无需运行这些命令。

### 15.1 Docker 服务

确保 Docker Desktop 已运行，且 `backend/.env` 已正确配置。

```bash
# 查看状态与日志
docker compose ps
docker compose logs --tail=100 frontend api worker

# 启动已构建服务
docker compose up -d --no-build --wait

# 重启
docker compose restart frontend api worker

# 停止，不删除宿主机业务文件
docker compose stop

# 重新构建并部署代码
docker compose build api frontend
docker compose up -d --no-build --wait
```

默认网页端口为 5173，宿主机后端端口为 8001。前端通过 Nginx 同源代理访问 API，不需在浏览器单独打开后端端口。

容器访问宿主机服务时，检查 `host.docker.internal:端口` 与精确白名单。USB 设备、ADB 和本机 Mobile MCP 需按实际部署方式单独维护；Docker Compose 不会自动启动这些外部服务。

### 15.2 数据库与账号

```bash
# API 启动时自动迁移；也可手动执行
docker compose exec api python manage.py migrate --noinput

# 创建管理员
docker compose exec api python manage.py createsuperuser

# 检查配置
docker compose exec api python manage.py check

# 清理到期审计记录，使用当前系统保留配置
docker compose exec api python manage.py cleanup_audit
```

不要通过重置数据库来解决普通登录或连接问题。

### 15.3 密钥和网络配置

- 将实际业务密钥保存为服务端环境变量，前端使用引用。
- 修改模型、MCP 或目标地址时同步检查 `TESTPILOT_ALLOWED_TARGETS` 的精确主机和端口。
- 修改 `.env` 后重启 API 和 Worker，使配置生效。
- 不应通过关闭鉴权、扩大白名单或跳过 TLS 校验来消除连接错误。

### 15.4 备份和恢复

1. 在维护时段停止服务，确保 SQLite 和附件处于一致状态。
2. 同时备份 `backend/db.sqlite3`、`backend/media/`、`backend/.env`，以及存在时的 `backend/.secret_key`。
3. 妥善保存凭据加密密钥 `CREDENTIAL_KEY`；如使用独立 MCP 凭据文件，一并安全备份。
4. 恢复文件和相同密钥后执行迁移，再启动服务并验证登录、附件下载和资源连接。

只恢复数据库不能恢复附件；丢失加密密钥可能导致已有凭据无法解密。重建容器通常不删除宿主机持久化数据，但删除宿主机目录会造成实际数据损失。

### 15.5 非 Docker 开发启动

仅用于需要本地开发的场景，避免与 Docker 争用端口或重复启动 Worker。

```bash
# 终端一：API
source .venv/bin/activate
python backend/manage.py runserver 127.0.0.1:8000

# 终端二：Worker
source .venv/bin/activate
python backend/manage.py runworker

# 终端三：前端
cd frontend
npm run dev
```

前端默认代理到本地 8000。需要连接 Docker API 时，按 README 使用 `TESTPILOT_API_TARGET` 配置。不要用 file:// 直接打开前端文件。
